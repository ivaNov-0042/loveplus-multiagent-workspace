# NEW ラブプラス+ 内 Siren14 语音解码链的静态还原与可复现实现

本报告记录《NEW ラブプラス+》卡带 `code.bin` 中 Siren14 语音解码链的还原结果：从索引表与参数块出发，逐层还原「码流 → 640 个 MLT 系数 → PCM」，给出可复现的 Python 实现、验证数字，以及与 FFmpeg G.722.1 实现的差异与已知局限。目标是让仓库内其他人在解同一批语音或把该链移植到别处时，不必重走定位与试错的过程。

全文结论都可复现：合成层自检把分析核与标准 MDCT 定义式逐元素比对，检查窗正交条件（最大偏差 4.4e-16）与往返重构（补归一化系数后相对误差 2.4×10⁻⁷）；真实语音上用两套等价排布交叉核对，结果逐样本一致。报告只陈述能复算的量，涉及固定增益、未逐样本对照的部分单列在「遗留」。

## 1. 目标与素材

### 1.1 素材清单

| 文件 | 大小 | 作用 |
| --- | --- | --- |
| `code.bin` | 4.2 MB | ExeFS ARM11 可执行体（加载基址 `0x00100000`），解码器实现所在 |
| `audio/Siren14Voice.spp` | 687534906 B | 语音码流本体 |
| `audio/Siren14voice.bin` | 724 KB | 索引表，92655 条 `(off, size)` |
| `audio/Siren14Voice.dpb` | 16 B | 解码参数块 |
| `audio/bcsar/*` | 26 MB | 音效库容器，与语音链无关 |
| `audio/stream/*.bcstm` | 161 MB | BGM 流，与语音链无关 |

`code.bin` 的加载基址是 `0x00100000`，本报告的地址一律写虚拟地址（VA）。

### 1.2 索引表与参数档

索引表 `Siren14voice.bin` = 92655 条 × 8 B 的 `(off, size)` 小端 u32 对，逐项验算结果：

| 检验项 | 结果 |
| --- | --- |
| 条目数 | 92655 |
| offset 单调 | 成立（`off[i] <= off[i+1]`） |
| size 全为 46 的倍数 | 成立（最小 46） |
| 覆盖率 | `max(off + size) = 687534906` = `.spp` 文件大小，100% 覆盖 |
| 空条目 | `voice 92654` 的 `size = 0` |

播放时只按 `id` 取一条 8 B 索引项、再去 `.spp` 读对应区间，因此 687 MB 无需整载。

参数块 `.dpb` 是 16 B，四个 LE u32 = `{23, 1, 1, 16}`，语义由驱动代码 `0x68b950` 确认（`码率 = dpb[0] × 800`、`采样率参数 = 7000 << dpb[1]`、`声道 = dpb[2]`、`位深 = dpb[3]`）：

| 字段 | 值 | 语义 | 推出的参数 |
| --- | --- | --- | --- |
| `dpb[0]` | 23 | 每帧 16 位字数 | 码率 `23 × 800 = 18400` bps |
| `dpb[1]` | 1 | 带宽选择 | `7000 << 1 = 14000` Hz |
| `dpb[2]` | 1 | 声道数 | 单声道 |
| `dpb[3]` | 16 | 位深 | 16 bit |

由此确定的解码参数档为：**18400 bps、32 kHz 采样、640 样本每帧、28 region、5 bit（32 种）速率控制、46 B 每帧（20 ms）**。解码器初始化函数 `0x142568` 只接受两个带宽参数：`7000 → 14 region / 320 样本`（16 kHz 那一支）与 `14000 → 28 region / 640 样本`（本作走这一支）。

帧长三处互证：`bits/帧 = 码率 ÷ 50 = 18400 / 50 = 368 bit = 46 B = 23 × u16`，与 `dpb[0] = 23`、与索引里 size 全为 46 的倍数一致。368 bit 属本作为语音定制的低速率，条目内部没有更细的组帧。

## 2. 位流层：码流 → 640 个 MLT 系数

### 2.1 函数地址

`code.bin` 的 `0x75c000-0x767000` 是本作内置的 G.722.1 家族实现库。

| 函数 | 地址 | 职责 |
| --- | --- | --- |
| 帧解码总入口 | `0x75e69c` | 位流 → 一帧系数 |
| 包络解码 | `0x75e0c0` | 解析 ESF 与逐 region 差分索引 |
| 区域分类（二分） | `0x75c3dc` | 与 `0x75c500` 的 min/max 调整循环配合 |
| min/max 调整 | `0x75c500` | 产出 `balance[]` |
| 码向量解码 | `0x75e2b8` | 逐区域走码树、拆下标、叠 dither |
| 索引拆解 | `0x766338` | 按行长整除拆分量下标 |
| 位读器状态 | `0x142454` | 逐帧封装，填好解码器字段后调 `0x75e69c` |

### 2.2 位读器

位读器按 **16 位小端字**取字节，**字内 MSB-first** 消费。这一约定由 `0x142454` 初始化（`*(st+0x1408)=0` 位计数、`*(st+0x140a)=*frame` 首字）与 `0x75e69c` 的取位循环共同确定。

### 2.3 帧级算法

```
frame_decode(br, coefs_out, nregions=28):
    rc_bits, n_rc = (4, 16) if nregions == 14 else (5, 32)
    decode_envelope(br, nregions, std_dev[], power[])     # 0x75e0c0
    rate_control = br.read(rc_bits)
    categorize_regions(nregions, br.bits_left, n_rc, power, cats, balance)   # 0x75c3dc
    for i in 0..rate_control-1:
        r = balance[i]
        if cats[r] < 7: cats[r] += 1                      # 跳过已达 7 的区域
    decode_vector(br, coefs_out, nregions, std_dev, cats) # 0x75e2b8
```

包络解码：`ESF = read(5) - 7`；区域 1..27 各走一次差分码树（叶值 `<= 0` 时增量 `= -叶值`，`power[i] = power[i-1] + 增量 - 12`）；最后 `std_dev[i] = table_0x801d34[clamp(power[i] + 24, <= 53)]`。

区域分类与 FFmpeg 同构：`offset = -32`、`delta` 从 32 折半到 1 的二分，`cat = clamp((offset + delta - power) >> 1, 0, 7)`，当 `Σ expected_bits_table[cat] >= available - 32` 时 `offset += delta`；再跑 `n_rc - 1` 次 min/max 调整产出 `balance[]`。本作有两处与 FFmpeg 不同：`n_rc` 是参数（16 或 32，`balance` 长度 `n_rc - 1`），以及施加速率控制时跳过已为 7 的区域且最多走 `len(balance)` 步。

本作另有一条 FFmpeg 没有的可用位数上限：`K = nregions/14`、`cap = 320·K`，当 `available > cap` 时按 `available = cap + (available - cap)·5/8` 收缩。46 B 帧给出的可用位数约 230 bit，远小于 `cap = 640`，该规则在本作码率下不触发。

码向量解码：`cat < 7` 的区域重复 `number_of_vectors[cat]` 次「走码树得码字 → 拆成 `vector_dimension[cat]` 个量化下标 → 每个非零下标读 1 个符号位」；系数按 Q12 乘加四舍五入（`(mlt_quant[cat][digit] · std_dev + 0x800) >> 12`）得到，输出 i16。`cat >= 5` 时叠舒适噪声：`noise = (noise_table[cat-5] · std_dev + 0x4000) >> 15`，每 10 个系数取一次 4 字 LFSR 的 16 位字，逐位决定 ±noise 写入仍为 0 的系数。

### 2.5 码本等价性判据

游戏码树是堆式布局，下标拆解用按行长整除（`digit = code % d; code //= d`，且 digit0 落在输出数组末位），与 FFmpeg 的「值即下标、奇数为叶」加 2 的幂掩码在字面上完全不同。判据取两者的可观测输出：枚举所有比特路径，比较两套码本给出的分量下标元组。7 类共 1276 条路径全部一致。

| 类别 | 路径数 | 元组一致 |
| --- | --- | --- |
| cat0 | 181 | 181 |
| cat1 | 94 | 94 |
| cat2 | 48 | 48 |
| cat3 | 520 | 520 |
| cat4 | 209 | 209 |
| cat5 | 192 | 192 |
| cat6 | 32 | 32 |

两套存储描述同一个标准 G.722.1 码本，因此本作 `.spp` 流是标准 G.722.1 流，FFmpeg 派生的表可以直接复用，只需改参数（28 region / 640 样本 / 32 kHz / 5 bit 速率控制）。

### 2.6 一条被证伪的判据

最初设计的判据是「一帧解完必须正好用掉 368 bit」。实测不成立：编码器不填满帧，逐帧统计显示整帧剩余 0~21 bit（voice 0 前 40 帧里 8 帧恰好填满，其余留零或随机尾）。决定性的判据改为 2.5 节的分量下标元组一致；帧尾余位只作解析对齐的独立佐证，用于「解码未跑飞、未越界」的回归检查。

### 2.7 std 表语义

`0x801d34` = 54 项 i32，是 **Q0** 的 `round(2^((i-24)/2))`，索引 `i = arp + 24`，`arp ∈ [-24, +29]`。三个锚点：`std[24] = 1`、`std[0] = 0`、`std[53] = 23170`。回放增益最大可达 `2^14.5`，响帧（arp 18-20）的系数合法地可达 1e5 量级：实测最响帧 `max|coef| = 136613`，而 `q·std` 的比值仍 ≤ 4.724，落在码本上限内。据此，响帧的系数幅度落在该表的正常取值范围内。

## 3. 变换层：640 个系数 → PCM

### 3.1 合成式与窗

记 N = 每帧样本数 = 每帧系数数 = 640，窗长 2N，hop = N：

```
y[m] = Σ_k X[k]·cos(π/N·(m + 0.5 + N/2)·(k + 0.5))     m = 0..2N-1
w[m] = sin((m + 0.5)·π/(2N))
pcm[i] = w[i]·y_k[i] + w[N+i]·y_{k-1}[N+i]              i = 0..N-1
```

### 3.2 游戏侧的定点实现

| 函数 | 地址 | 大小 | 职责 |
| --- | --- | --- | --- |
| 窗 + 重叠相加 | `0x76b67c` | 300 B | 调 IMDCT → 加正弦窗 → 与上一帧尾相加 → 写 PCM |
| 快速 IMDCT | `0x75dd2c` | 896 B | 定点逆 MLT（N = 640 或 320） |

定点证据：i16 乘、`>> 0xd / 0xe / 0xf`、`+ 0x1000` 等四舍五入常数、以及负向饱和到 `0x8000`（池常数 `0x7fff`）。

`0x75dd2c` 是快速的 10×2^k 分解实现（640 = 10×2⁶，320 = 10×2⁵），四段结构：

1. 前置蝶形：按 `(a+b+1)>>1`、`(a-b+1)>>1` 处理 N 个输入，符号决策取自位模式表 `0x8bf8fc`（320 用）或 `0x8bf924`（640 用）。
2. log2 级基 2 蝶形：双缓冲乒乓。
3. 10 点逆 DCT-IV 核：表 `0x801eb4`（i16 Q15，`tab[j] = round(32768·cos((2j+1)π/40))`），按 5 元素步长阶梯索引，`(Σ + 0x4000) >> 15`。
4. 旋转级：表 `0x8bf974`（i16 (cos,sin) 对，Q14，`>> 0xe`），复数式旋转，最后 memmove 到输出。

窗表三张，均为 i16 交替 (sin, cos) 对，幅度 `G = 18317`：

| 表 | 地址 | 长度 | 用途 | 相位 |
| --- | --- | --- | --- | --- |
| A | `0x802954` | 640 i16 | N = 320 帧 | `φ_j = (j+0.5)·π/640` |
| B | `0x802e54` | 640 i16 | N = 640 帧前半 | `φ_j = (j+0.5)·π/1280` |
| C | `0x803354` | 640 i16 | N = 640 帧后半 | `φ_{j+320}` |

三张表对 `G·(sin φ, cos φ)` 的最大偏差 ≤ 0.99 LSB（最佳 G 均为 18317），即窗函数 `w[k] = G·sin((k+0.5)·π/1280)`，与 FFmpeg 的 320 点正弦窗同形。

`0x76b67c` 的语义是「窗 + 重叠相加」：先取 `coefs → buf[N]`，再对 `j = 0..N/2-1` 输出 `out = sat((c_j·prev_tail[j] + s_j·buf[N-1-j] + 0x1000) >> 13)` 并保存新尾 `buf[N/2..N]`。50% 重叠、hop = 320，每帧输出 640 样本（20 ms @32 kHz），上一帧尾缓冲每声道 0x280 B = 320 i16。

### 3.3 输出标量

未归一化逆变换的最响帧峰值为 252250；任何大于约 1/7.7 的整体标量都会削波。实现取 `out_scale = sqrt(2/N)/32768`，N = 640 时为 1.706e-06，得到 voice 0 峰值 0.430、RMS 0.0969（约 −20 dBFS）。备选的 `1/32768` 会削波，`2/N` 归一化后峰值仅 0.024。该标量与官方解码器的逐样本电平未对齐，属于整体增益（±6 dB 内），需要时用 `--gain` 覆盖。

### 3.4 相位约定

合成端**不做 (−1)^k 翻转**，三条判据：

1. 分析核 `imlt_basis().T` 与标准 MDCT/MLT 定义式 `cos((2j+1+N)(2k+1)π/(4N))` 逐元素完全一致（偏差 0）。
2. 补 2/N 归一化后（分析, 合成）完美重构，相对误差 2.4e-07。
3. FFmpeg `libavcodec/siren.c` 的「折叠输出 + 旋转式重叠相加」排布，在不翻转系数时与本实现逐样本一致（真实语音约 2.0e-07）。

若对偶下标取负，会得到另一条与本实现互相关接近 0 的信号，故不采用。FFmpeg 源码里的 `imdct_in[i] *= -1` 属其通用逆 MDCT（AV_TX）的输入约定，逐字抄录其 naive 参考实现无法复现原信号，不作判据。

## 4. 整帧流水线 `0x1420dc`

`0x1420dc`（848 B）是整帧调度与**系数域混音**：

```
fcn_1420dc(obj, nch, pcm_dst[]):
    memset(obj + ch*0x500, 0x500)          for ch: 清整个 640 系数缓冲
    for i in 0..31:                        # obj+0xf00 起的 32 个 voice 槽
        if 槽空 or 被 obj+0xf84 的 bit i 禁用: continue
        0x142454(v, 0, n, v+2)             # 位流 → 系数（内部调 0x75e69c）
        step = frame_len*14/16             # 640 → 560
        for ch, k in (nch, step):
            obj[ch*0x500 + k] += sat((v_ch[k]*vol*gain + 0x2000) >> 14)
    for ch: 0x76b67c(obj + ch*0x500, obj + ch*0x280 + 0xa00, pcm_dst[ch], obj[0xf88])
```

要点：

- 混音在 MLT 系数域完成。变换是线性的，系数域累加与时域混音等价，而整帧每声道只需一次 IMDCT 与一次窗重叠，32 路语音共享同一帧格式（28 region / 640）。
- 累加只覆盖前 560 个系数（`step = 640 × 14/16 = 560 = 20 × 28`），其余 80 个恒为 0，对应 14 kHz 带宽上限，与位流只编码 560 个系数互证。
- 每帧 memset 整个 640 系数缓冲（每声道 0x500 B = 1280 B = 640 i16），上一帧尾缓冲每声道 0x280 B；`obj+0xf90` 记录本帧是否有 voice 解码成功，无则输出静音。

## 7. 与 FFmpeg 的差异与局限

1. FFmpeg `libavcodec/siren.c` 只实现 14 region / 320 样本 / 16 kHz 一支，本作是 28 region / 640 / 32 kHz。移植时必须泛化帧长与参数：`frame_size = 320·nregions/14`、`rate_control_bits = 4 + log2(nregions/14)`。
2. 噪声填充幅度取值方式不同。FFmpeg 用随 `|coef|` 是否超过 `2·std` 变化的多档噪声类别，本作是单一类别平台值（`0x8bf98c` 的三个 Q15 常数）。低非零系数区域的舒适噪声幅度会不同。
3. 尾部系数处理不同。FFmpeg 保留多出槽位的陈旧值，本作每帧清零整个缓冲且只累加前 560 个系数，移植时应按本作清零。
4. 本作在 MLT 系数域做多路混音，属引擎架构；变换线性，与时域混音等价。
5. 游戏变换层是定点（Q13/Q14/Q15 加饱和），本实现是 float，差异在 ±1 LSB 量级。
6. 绝对增益未与官方解码器逐样本对齐。`out_scale = sqrt(2/N)/32768` 是教科书正交归一除 Q15 口径，整体增益误差在 ±6 dB 内，需要精确电平须按 8 所述做定点仿真或调 `--gain`。
7. 相位约定的三条判据见 3.4；对偶下标取负会得到互相关接近 0 的另一条信号，故不采用。
8. 游戏定点 IMDCT 的旋转级符号只核了窗表与结构，没有逐样本对照。要绝对对齐需按 3.2 的四段结构与三张表做定点仿真，再逐样本比较。

另有一片需要澄清的代码：`code.bin` 的 `0x76d000-0x76f000` VFP 指令密集，曾被视为变换层候选。它没有 `push {..., lr}` 型序幕，全仓没有 `bl` 指向该区，只经函数指针表 `0x76bc34` 间接调用，且调用者全在 `0x765xxx`，再往上是 SE/BGM 引擎。语音链对 `0x75c000-0x772000` 的全部直接调用只有 `0x75c3b8`、`0x75c7d8`、`0x75e69c`、`0x76b67c` 四处。该区属于另一个编解码器或音效内核，与 Siren14 语音无关。

## 8. 遗留

1. 定点 IMDCT 的逐样本对照：按 §3.2 的四段结构与三张表写定点仿真，消掉第 7 节第 8 条的残留不确定性，同时把绝对电平对齐到官方解码器。
2. `0x76d000-0x76f000` 那片 VFP 密集代码具体属于哪个编解码器或音效内核，需要解 BGM/SE 时才处理。
3. 噪声填充幅度与 FFmpeg 的多档取值差异只做了结构比对，未做听感层面对照。
